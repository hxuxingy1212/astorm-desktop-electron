# Web 端（单用户云容器）与桌面端功能差异

> 面向：部署/使用云容器的用户与二次开发者。架构与部署见
> [cloud-server.md](./cloud-server.md)、[deployment.md](./deployment.md)。

## 0. 前提：同一套前端 + 同一个内核，两种宿主

| | 桌面端（Electron） | Web 端（单用户云容器） |
|---|---|---|
| 渲染层 | 同一套 Vue 工程 | 同一套 Vue 工程（静态产物由服务端同源托管） |
| 桥 | preload 暴露 `window.api`（~65 条 IPC 通道）→ 主进程 → `astorm-napi`（.node，进程内） | `web-bridge.js` 注入同形 `window.api`（浏览器无 preload 时启用）→ REST `/api/v1/*` + WS 事件 + `/api/v1/bridge`（直调 core facade） |
| 内核 | `astorm-core` | **同一个 `astorm-core`**（服务端与 napi 是它的两个宿主，逻辑不分叉） |
| 数据 | `%APPDATA%\astorm`（本机） | 卷 `/data`（一容器一实例一用户） |
| 额外入口 | — | CLI（`astorm`）+ HTTP API（`/api/v1`） |

所以差异几乎全部来自**「宿主能力」而非业务逻辑**：浏览器里没有的（原生对话框、
系统窗口、本机 Chromium/CDP、本地文件路径）就是降级点。

**第三种形态：桌面壳子接云容器**（2026-10-13）。Electron 启动时先走引导
（欢迎 → 选择连接方式 →〔仅本机〕配置模型 → 偏好，偏好可跳过；端点 + 访问令牌，带测试连接，
模型带预设与真实探测；随时可在菜单「连接方式…」或设置页「连接方式」改）：选云端就把窗口直接指向容器端点——渲染层仍是
服务端托管的那份 Web UI（与浏览器访问同一个页面），只是换成原生窗口（菜单栏/标题栏/Dock
图标），本机不启后端、不落本机数据，令牌由 `preload/cloud.js` 预先写进远端 localStorage
免登录遮罩。详见 [cloud-server.md](./cloud-server.md) 的「Electron 壳子」节
（含 `pnpm run test:e2e:onboarding` 引导 e2e）。

## 1. 功能对照

### 1.1 完全一致（已实测）

| 能力 | 说明 |
|---|---|
| 会话全流程 | 新建/列表/回读/流式渲染/多工具真实执行/表单卡/审批卡（同意·拒绝·当前会话允许）/模式与权限切换/撤回 rewind/fork/摘要/删除/自动标题 |
| 终端（PTY） | 交互式 shell 全功能；**切换页签与会话不断连、关闭页签才断开**（shell 在服务端持久）。提示符：web 容器内为 SSH 风格 `[user@host /path]#`（`bash --norc` + PS1），桌面沿用 `$SHELL` |
| 文件读写/预览 | 会话工作区文件树、文本/图片/md 预览、代码高亮、git 变更审查 |
| office 预览 | docx / xlsx / pptx / pdf：桌面用本机 office CLI，web 用服务端同一套 CLI（`/api/v1/office/preview`） |
| 附件 | 选择/拖拽/粘贴 → 上传到服务端 staging → 随消息发送；图片缩略图两侧都经 `attachment.toUrl()` 契约 |
| 知识库 / 长期记忆 | 文件树、读写、导入、编译管道、概念检索 |
| 邮件 | 多账号、文件夹、列表、正文、附件、发送 |
| 定时任务 / 交付物·资料库 / 使用统计 / 审计查看 | 列表、创建、编辑、运行、查看 |
| 技能 / 智能体 / 工具 / 全局约定（AGENTS.md）/ 设置聚合 | 增删改查 + 热更 |
| 模型供应商配置 | 添加/编辑/排序/删除、文本+图片识别「检测」、保存即热更；默认模型 = 列表第一项供应商的第一个模型 |
| tabs 工具 | 页签镜像与按会话页签操作（与桌面同协议） |
| 内置浏览器页签 | 页签能开、能导航、能跟随激活项滚动；页面本体：桌面 = iframe（主进程 CDP 桥），web = 服务端 Chromium **画面流**（canvas + 鼠标/键盘回传），两侧都与 AI 的 `browser` 工具操作同一页面 |

### 1.2 有差异（降级或形态不同）

| 能力 | 桌面端 | Web 端 | 差异性质 |
|---|---|---|---|
| 附件选择 | 原生对话框（多选、目录） | 浏览器文件选择 + 上传（单文件 20MB，staging 24h TTL 自动清扫） | 形态不同 |
| 粘贴截图 | 静默读系统剪贴板 | `navigator.clipboard.read()`，需浏览器授权 | 形态不同 |
| 拖拽文件 | 可直接用本地路径 | 一律走上传 | 形态不同 |
| 目录选择器（新建会话的项目目录、定时任务工作目录、设置里的用户目录） | 原生目录对话框 | 服务端目录浏览模态（面包屑 + 目录列表 + 新建文件夹 + 手输路径，限数据根内） | 形态不同 |
| 在系统文件管理器中打开 / 用默认应用打开 | ✓ | ✗（浏览器无此能力；入口在 web 下隐藏，或降级为提示路径） | 降级 |
| 页面弹窗 / `window.open` / `target=_blank` | 主进程 `setWindowOpenHandler`：有浏览器桥 → **转内置新页签**，否则系统浏览器 | 应用侧：`window.open` 由 `web-bridge` 拦下 → **当前浏览器面板就地导航**（面板页签共享同一台会话浏览器，开新页签只会看到同一页）；被浏览页面内：服务端注入脚本把 `_blank`/`window.open` 改成本页导航 | 形态不同（都留在内置浏览器里） |
| 审计导出（另存为 JSONL） | ✓（原生保存对话框） | ✓（浏览器 Blob 下载） | 形态不同 |
| AI 操控浏览器（`browser` 工具） | ✓（agent-browser CLI 附着主进程 CDP 桥驱动内置页签） | ✓（**同一条路**：镜像内置 agent-browser CLI，附着服务端自有 headless Chromium；CLI 缺失时回落 core 直连 CDP） | 形态不同（页面宿主不同，驱动一致） |
| 元素拾取 / 页签截图 / 取帧 / 录制 / iframe DevTools | ✓ | ✗（明确报错；依赖桌面 CDP 桥与原生窗口） | 降级（与浏览器工具本身无关，面板画面流已可用） |
| Chrome cookie 导入 | ✓ | ✗（容器无本机浏览器） | 降级 |
| MCP | 连接/断开/列工具 ✓（同一实现：core 的 `mcp` 模块，主进程只转发命令）；远程 401 → OAuth（系统浏览器 + 本机回环）/ 手动 Token ✓ | ✓ 连接/断开/列工具；远程 401 → **手动 Token / headers** ✓，OAuth 浏览器授权 ✗（回环回调无法到达容器） | 基本一致（授权方式有差异） |
| 插件 | 安装（本地目录）、配置保存、插件站点（`astorm-plugin://` + iframe 宿主）✓ | 仅扫描/列表；安装与站点面板 ✗——设置页「插件」在 web 下已隐藏 | **不做**（入口已隐藏，容器形态不引入插件） |
| PPTX 解包 | ✓（插件站点面板用） | ✗ | 降级（随插件） |
| 窗口控制（最小化/最大化/关闭） | macOS 原生红黄绿 / Win·Linux 自绘 | 不渲染（浏览器自带窗口按钮） | 形态不同（web 走「无窗口装饰」布局） |
| 缩放因子 / 全屏状态 / 拖拽移动窗口 / 系统权限（麦克风·摄像头·屏幕录制等）/ 保持唤醒 | ✓ | no-op（浏览器自身能力替代） | 形态不同 |
| 凭据存放 | `providers.json` + `safeStorage` 加密 apiKey | 卷内明文 JSON（卷权限即边界）+ 支持 `${ENV}` 占位 | 安全模型不同 |
| 更新方式 | 重装/升级安装包 | 换镜像重建容器（数据卷不动） | 运维形态不同 |
| 多端访问 | 仅本机窗口 | 浏览器 + CLI + HTTP API，可多设备同时用（仍是单用户） | Web 端独有 |

## 2. web 下「看得见但会失败」的按钮

第一轮普查的粗糙点已全部处理（2026-10-11，commit `4c411ba`）：目录选择改服务端浏览模态、审计导出改 Blob 下载、无文件管理器场景的按钮改为隐藏或提示路径。当前仍在 UI 上、web 下不可用的是**设计内降级**：

| 位置 | 行为 |
|---|---|
| 浏览器面板的拾取/截图/录制/DevTools 按钮 | 明确报错（依赖桌面 CDP 桥与原生窗口；面板本体与画面流不受影响） |
| 设置 → 插件 | web 下整个页面入口已隐藏（直链访问会重定向回默认页） |
